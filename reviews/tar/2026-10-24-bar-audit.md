# Bar audit: tar pilot, 2026-10-24

- Subject: [Proven-Commons/tar](https://github.com/Proven-Commons/tar) at commit `7517a86` (main on 2026-10-24).
- Measured against: the verified bar in `README.md` and `FOUNDING-BRIEF.md` of this repo at commit `ca367b1`.
- Written by: Claude, an AI agent working for the org owner. This is an adversarial review (factory step 5). It is not the spec approval that bar item 1 asks for. See [reviews/README.md](../README.md).
- Tools: Lean 4.35.0 (commit `eb6cafb`), Python 3.13.17, GNU tar 1.35, bubblewrap 0.9.0, Linux x86_64.

## Verdict

The pilot does not yet meet the verified bar. Two items are met, two are partly met, and two are not met.

The proofs that exist are sound. Lean's kernel and the five other kernels shipped with Lean 4.35 accept them, and they use only the standard axioms. The problem is what they state. The headline theorem says less than the public claim that no file in an archive can be written outside the destination folder (F1). The code is safe on every input tried here. The proof does not yet show it.

The project page also makes two statements that are false (F2, F3), and the command-line tool does not call the proved function (F5).

Until the fixes below land, neither repo should call the pilot verified or complete. This repo's README now calls it built, not yet verified.

## Findings

### F1. The headline theorem does not state the headline claim

The claim, on this repo's README and on the tar page: no file in an archive can be written outside the destination folder, and "a machine-checked proof shows the cleaned path can never climb out of the destination".

The theorem, `extractAll_safe` (`TarPilot/Archive.lean` line 74): every emitted path is the destination followed by a non-empty list of components, none of which is `..`, empty, or `.`.

The gap: nothing says a component cannot contain `/`. The one-component list `["../../etc/passwd"]` satisfies the statement. `runManifest` joins components with `/` (`Main.lean` line 50), which gives `out/../../etc/passwd`. A gate that never splits the name on `/` proves the exact statement of `gate_sound`.

Evidence: [evidence/WeakStatement.lean](evidence/WeakStatement.lean). Inside a tar checkout, `lake env lean WeakStatement.lean` prints:

```
some ["a/../../etc/passwd"]
'escaping_path_is_published_safe' depends on axioms: [propext]
'badGate_sound' depends on axioms: [propext, Classical.choice, Quot.sound]
```

Is the code unsafe? No. Its components come from `splitOn "/"`, so none holds a `/`. That is an unproved fact about `String.splitOn`. The proof does not carry it.

Fix: [evidence/Contained.lean](evidence/Contained.lean). It adds one check to the cleaner (reject a component holding `/` or NUL, which today's code never produces) and proves two statements with the standard axioms only. `extractAll_contained`: every emitted path is the destination followed by a non-empty list of plain names. `extractAll_resolves_inside`: resolving the emitted path the POSIX way gives the resolved destination followed by those names. The new gate agrees with the old one on every name in the pilot's tests.

Why this matters past tar: every machine check in the current bar passed. No `sorry`, standard axioms, tests green. None of them can notice that a theorem states less than its claim. Only a reviewer reading the statement against the claim can, which makes bar item 1 the item everything else rests on.

### F2. GNU and pax archives are read wrongly, not rejected

The page says GNU extensions and pax headers are not supported, and "an archive using them fails to parse instead of being read in a wrong way" (`README.md` line 39).

What happens: exit code 0. A long name is cut to its first 100 bytes, losing `.txt`. A pax path override is ignored, so the file is read under its old name. A pax non-ASCII name is read as `caf?/notes.txt`. This covers the default output of GNU tar 1.35 (`--format=gnu`) and of Python's `tarfile` (pax).

Every path still lands inside the destination, because the gate still runs. Even a pax override that climbs out (`../../etc/cron.d/x`) is read as `out/safe.txt`. But the pilot reads a different archive than other tools do, and the page says it will not.

Evidence: [evidence/probe_formats.py](evidence/probe_formats.py), run as `python3 -I probe_formats.py <tar>/.lake/build/bin/tar-pilot`.

Fix: reject entries with typeflags `L`, `K` (GNU long name and long link), `x`, `g` (pax), and any other type outside the supported set, so the page becomes true. Or implement them.

### F3. Names with invalid UTF-8 are not always rejected

The page says "names that are not valid UTF-8 read as empty and are rejected by the gate" (`README.md` line 39).

What happens: `bytesToName` reads invalid UTF-8 as the empty string (`TarPilot/Header.lean` line 38), and `parseBlock` then joins the prefix and name fields as if that field were empty (line 57). An invalid prefix with a valid name drops the prefix, so the file lands at `out/qqq…/file.txt`. A valid prefix with an invalid name puts the file at `out/ppp…`, the name of the prefix directory itself. Only when both fields are invalid is the entry rejected. Same evidence script.

Fix: have `bytesToName` return `Option String` and reject the header when either field is not valid UTF-8.

### F4. Contiguous files are skipped without saying so

An entry with typeflag `7` (contiguous file) is skipped. Python's `tarfile` reads it as a regular file, and POSIX lets a reader do the same. The page does not mention it. Same evidence script.

Fix: extract typeflag `7` as a regular file, or list it on the page as skipped.

### F5. The command-line tool does not call the proved function

`extractAll` and `extractArchive` are proved. `runManifest` (`Main.lean` lines 37 to 54) re-implements the same loop: `isRegular`, then `gate`, then the join. The differential tests drive the command-line tool, so the tests and the proofs cover two different pieces of code. Today they agree by reading. Nothing checks it.

Fix: have `runManifest` call `extractArchive` and print its result.

### F6. The pilot's own checks let faults through

Evidence: [evidence/plant_faults.py](evidence/plant_faults.py) copies a checkout to a temporary directory, plants each fault in `TarPilot/Path.lean`, and records the exit codes:

```
## fault: sorry
lake build exit:          0
tests/run_tests.py exit:  1  (15/16 checks passed; ...)

## fault: axiom
lake build exit:          0
tests/run_tests.py exit:  0  (16/16 checks passed; ...)
TEST-RESULTS.md records:  'TarPilot.gate_sound' depends on axioms: [propext, Classical.choice, Quot.sound, TarPilot.cheat]
```

With `axiom cheat : False` behind `gate_sound`, every check passes and the results file lists the bad axiom without failing. The cause is `tests/run_tests.py` line 224, which looks only for `sorryAx`.

Fix: check the axiom list against the allowed set `propext`, `Classical.choice`, `Quot.sound`, or use `lake check`, which fails on any other axiom.

## What holds

- A clean clone builds, and all 16 differential checks pass.
- All four theorems use only `propext`, `Classical.choice`, and `Quot.sound`.
- `lake check --paranoid` passes: Lean's kernel, `leanchecker-paranoid`, `lean4lean` (58011 declarations), `nanoda`, `con-leche` and `con-ron` (58014 declarations each) all accept the project.
- No probe in F2 to F4 made the pilot emit a path outside the destination.

## Fixes for the tar repo, in order

1. F1: adopt the cleaner and theorems from `evidence/Contained.lean`, and state on the page the theorem actually proved.
2. F5: have `runManifest` call `extractArchive`.
3. F2, F3, F4: reject unsupported typeflags and part-invalid names, add the probes as test cases, and correct the page.
4. F6: check axioms against the allowed set, and make `lake check --paranoid` the one re-check command.
5. Item 4: add seeded random and mutated inputs (for example, valid headers with fields flipped), and record the seed, input count, and oracle version in `tests/TEST-RESULTS.md`.
6. Item 5: add hardware, the test oracle, and the path join to what a reader must trust.
7. Item 1: write the specification, have a reviewer who did not write it approve it, and record the approval.
8. Item 6: run the check in CI on every push.
9. Point the link to the org's home repo at `mission` (it says `proven-commons`, which now redirects).

{%- comment -%} Works out where one link in a document should go on the site, and sets lk_url for the caller. include.url the href as written, or as jekyll-relative-links left it include.dir the folder of the source file in the repo, such as "reviews/", or "" for the repo root include.self where a link to "#id" goes, or "" to leave it as it is A relative link is read the way GitHub reads it, from the source file's folder. It then goes to: - the page, if the target is a page of the site (a folder's README.md is the folder's page); - the file on GitHub, if it is a source file: one of the extensions below, a file with no extension, or anything under a dotfolder. GitHub Pages would download these instead of showing them; - the folder on GitHub, if the folder has no page; - the README on GitHub, for the root README.md, which is not a page; - otherwise the file on the site, and the link check catches it if it is missing. Links with a scheme, such as https: or mailto:, stay as they are. {%- endcomment -%} {%- assign lk_code = '.lean .py .toml .json .yml .yaml .sh .txt .cfg .in .lock' | split: ' ' -%} {%- assign lk_url
